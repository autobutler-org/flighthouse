# 0011. Command-line interface

- Status: Accepted
- Date: 2026-10-06

## Decision

`package:args` `CommandRunner` with four commands. Global options: `--config`, `--report-dir`, `--no-color`.

| Command               | Does                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------ |
| `collect`             | Runs the configured collectors and writes raw outputs to `<reportDir>/raw/<source>/`. In phase 1 it copies the configured tool outputs in; phase 2 adds the web runner. |
| `report`              | Reads raw outputs, runs the pipeline, writes `report.json` and `report.html`.              |
| `ci`                  | `report`, plus the baseline diff and gate ([ADR 0009](0009-baseline-and-ci-gate.md)).      |
| `baseline --update`   | Runs `report` and writes the baseline file. Without `--update` it prints the diff only.    |

- The `cli/` layer is the composition root. It reads files through `io/`, calls the pure pipeline, writes outputs,
  prints a summary table to stdout and failures to stderr, and returns an exit code.
- `CommandRunner` throws `UsageException`; that is caught in `cli/` and mapped to exit code `2`.
- `bin/flighthouse.dart` only calls the runner and sets `exitCode`.
- Every adapter runs even when another fails. All failures are printed, and the exit code is `3` if any input was
  unusable.

## Consequences

- `ci` and `report` share every stage up to the gate, so a local `report` shows exactly what CI will judge.
